## 1. 目标、交付范围与完成标准

本轮用户报告了两个需要优先解决的问题：不同动作清晰度不一致，新动作外貌与本人差距大。0.5 必须先建立可复用的人物标准，再制作动作。把旧小图统一放大、给每个动作分别生成一个“相似的人”，均不能作为问题已解决的依据。

| 用户需求 | 0.5 必须交付的结果 | 验收依据 |
| --- | --- | --- |
| 按新照片修正本人外貌 | 一套被确认的人物母版；现有广播操、娇羞、飞吻、打滚全部使用同一人物标准 | 照片与母版对照、跨动作接触表、桌面原尺寸播放 |
| 动作分辨率统一 | 同一有效采样密度、人物尺度、色彩和透明边缘标准 | 帧清单自动检查与白／灰／黑背景预览 |
| 更多动作 | 立定跳远、原地跳高、引体向上、俯卧撑、高难度街舞各至少一组完整动作 | 每组有准备、发力、主体、恢复阶段和回到站立的出口 |
| 外部 API | 用户可填写服务地址、模型和密钥；可手动聊天；离线功能完整可用 | 本地模拟服务契约测试；真实服务在用户配置后验证 |
| 可改人设 | 独立可编辑的 UTF-8 Markdown 人设文件、编辑与恢复默认入口 | 保存后下一条请求生效，重启保留 |
| 内容封装为项目 | 一个解决方案、清楚的源码／素材／工具目录、一键构建与发布、完整安装产物 | 干净检出构建，干净机器安装，包内无工作缓存与密钥 |

保留独立 Windows 桌面端、广播体操默认模式、漫画气泡、摸头爱心与好感度。新增运动默认从“运动动作”菜单手动播放；用户可自行加入轮播，不自动把广播操替换成高强度动作循环。

本文件默认“外 API”指外部文本对话服务。图像／视频生成只属于离线素材制作，不与桌宠聊天 API 混用，也不默认把人物照片发给用户配置的聊天服务。

### 3.2 必须保留与禁止漂移的特征

- 黑色蓬松短发的轮廓、额头与发际线关系；不能改成贴头皮发型。
- 深色上缘、透明／浅色下缘的眼镜形状及鼻梁位置；不能换成粗圆框。
- 饱满脸颊、下颌轮廓、自然肤色与皮肤纹理；不能自动瘦脸、美颜或变成幼态娃娃脸。
- 笑时眼睛收窄、嘴角和牙齿的可见关系；保留略微不对称，不生成统一的商业头像笑容。
- 维持原本身体体积和肩宽；不能为了运动动作把身体变成肌肉运动员，也不能再次缩短手臂。

0.5 提供可切换的黑色 T 恤与旧照片中的深色印花睡衣两套服装。下装、鞋和完整身体比例优先参考此前全身照片；缺失部分做明确标注的设计补全，不能称为照片中的真实细节。两套服装分别制作和验收，不在动作中途换衣；切换请求在当前动作结束后的安全站立帧生效。

### 3.3 母版制作与验收步骤

1. 先输出正面自然站立、正面微笑、左右四分之三视角及侧面母版。缺失视角是推定图，标注来源类型。
2. 将照片与候选母版并列，先看眼镜、发型、脸宽、下颌、笑容，再看肩宽、手长与衣服。提供正常桌宠尺寸与放大细节两种视图。
3. 同视角下标注头高／站立身高、肩宽／头宽、上臂／前臂比。以最终选定母版为比例基线；偏离 5% 先报警再复核，透视与弯曲姿势不机械套用直立阈值。
4. 母版通过用户外貌确认后冻结 `characterRevision`、文件哈希、参考编号和制作参数。确认之前只做少量候选，不批量生成整个动作库。
5. 每组动作都引用同一份母版和原始参考。允许生成局部姿势／遮挡，避免每一帧重新描述一个人物。不能把上一张已经变脸的结果不断作为下一张唯一参考。
6. 新姿势发生脸部漂移时，先修该关键帧再做过渡；不以连续补帧掩盖错误。保留失败原因和被淘汰帧清单。

这里的确认是后续制作的外貌验收点；本次用户已明确只要求规划，因此现在不启动生成或索要额外确认。

## 4. 成熟工具与动作制作路线

### 4.1 选型原则

运行端继续使用已有 WPF。制作端优先使用现成的参考图编辑、姿态控制、Blender 骨架与离线图像工具，不开发自己的生成模型、骨骼解算器或补帧算法。

| 路线 | 适用范围 | 采用方式与门槛 |
| --- | --- | --- |
| 同一母版的局部图像编辑＋关键帧 | 站立、摸头、飞吻、广播操小角度变化 | 作为第一条制作路线；每次编辑都带同一人物参考，先锁住脸和服装 |
| ComfyUI 姿态控制工作流 | 跳跃、俯卧撑的关键姿势约束 | 候选离线工具；模型与参考图能力须匹配，先做小样；姿态控制本身不保证人物身份一致 |
| Blender 骨架／动作重定向 | 高难度街舞的翻转、支撑和空间轨迹 | 用作动作预演、姿态与深度参考；最终仍需照片风格素材验收。若需完整三维人物，单独核算建模工作量 |
| 参考图驱动的视频生成 | 多帧姿态一致性的候选方案 | 先测一段站立转身和俯卧撑；逐帧检查脸与手脚，不能把生成视频直接等同成品 |
| 现有 RIFE 补帧 | 已经合格且位移较小的相邻帧 | 最后可选步骤；大遮挡、翻身、器械接触段默认不用；有重影就退回重新制作 |

ComfyUI 官方示例包含 Pose ControlNet；Blender 提供骨架与蒙皮工具。它们支持上述制作环节，但是否能在现有机器上完成本人物的照片风格动作，仍是后续小样需要验证的结论。[ComfyUI 官方示例](https://github.com/comfyanonymous/ComfyUI_examples/blob/master/controlnet/README.md)、[Blender 骨架文档](https://docs.blender.org/manual/en/latest/animation/armatures/index.html)。

### 4.2 先做三个技术小样

顺序为：站立→娇羞→站立；一次俯卧撑；街舞侧撑→翻转→另一侧撑。这三段分别验证人物身份、接地、复杂遮挡。记录工具版本、模型来源与许可、参数、种子（若工具支持）、耗时、显存、参考图哈希和失败帧。

若硬件不足，优先使用已授权的远端制作服务或降低工作分辨率做动作预演，不降低最终有效清晰度标准。正式模型与依赖版本在小样通过后锁定；本规划不承诺某个未测试模型必然解决身份一致性。

街舞小样不合格时，继续修姿势／更换成熟制作路线，必要时补充可授权的动作参考。可以先交其它动作的预览，但 **不能把摆动一张静态图称为完成高难度街舞，也不能将未完成项从 0.5 验收表删除**。

## 5. 清晰度、坐标与动画资产规范

### 5.1 固定尺度，区分画布与人物

以下是实施起点，先以一组母版和俯卧撑小样验证再冻结：

- 逻辑舞台 768×576 DIP，制作主画布 1536×1152 像素，即基准密度 2 像素／DIP。
- 自然站立人物建议高 320 DIP，对应约 640 个有效人物像素。所有动作共享同一身材尺度；蹲下、俯卧撑变矮是姿势变化，不通过把整个人缩小实现。
- 母版保留更高质量源图，发布默认使用 2×素材。桌宠缩放 × 屏幕 DPI 比例大于 2 时会超过基础素材的原生密度；界面说明清晰度范围，按需求后续增加高密度资产，不能承诺所有缩放均无损。
- 旧 192×208 小图只保留作动作参考；未通过高清重制的旧动作不得混入 0.5 正式皮肤。
- 画布可以不同程度留白，输出允许裁切透明区，但必须记录相对于主画布的裁切偏移。禁止每帧自动裁紧后按满框等比例放大。
- 统一 sRGB、RGBA PNG、正确 alpha；图像文件 DPI 元数据不参与人物尺度计算，所有换算使用 manifest 中的像素密度。

### 5.2 建议动作清单结构

下例只表示一帧的数据结构，不是完整可播放动作。`originDip` 是整段动作起点，`rootOffsetDip` 是相对起点的位移；二者和裁切坐标各只应用一次。

```json
{
  "schemaVersion": 3,
  "characterRevision": "pbb-photo-05-candidate",
  "id": "long_jump",
  "skinId": "black-tee",
  "stageDip": [768, 576],
  "pixelsPerDip": 2,
  "originDip": [220, 500],
  "referenceRootPx": [640, 1000],
  "playback": "once",
  "includeInRoutine": false,
  "requiredProps": [],
  "frames": [
    {
      "file": "frames/0001.png",
      "durationMs": 100,
      "cropRectPx": [300, 330, 680, 690],
      "rootOffsetDip": [0, 0],
      "headAnchorPx": [630, 390],
      "mouthAnchorPx": [632, 426],
      "contactAnchorsPx": {"leftFoot": [610, 1000], "rightFoot": [670, 1000]},
      "safeToInterrupt": true
    }
  ]
}
```

`cropRectPx`、头／嘴／接触坐标均使用未裁切主画布坐标。`referenceRootPx` 是素材主画布的基准脚底位置，`originDip` 是它在逻辑舞台中的摆放位置。帧的逻辑显示尺寸 = 裁切宽高 / `pixelsPerDip`；帧左上角 = `originDip + rootOffsetDip + (裁切左上角 - referenceRootPx) / pixelsPerDip`，然后加入窗口舞台原点并应用统一桌宠缩放与 WPF DPI 换算。头和嘴使用同一公式，将裁切左上角替换为相应锚点。实际实现只保留一条坐标换算函数，同时用于绘制、气泡和命中测试。素材制作时只画局部姿态，整段空间平移归根位移轨道，避免源帧与轨道同时记录同一位移。

首选每帧文件＋manifest，复用 WPF PNG 解码。只有性能基准表明文件 I/O 是瓶颈时才加图集；无论是否图集都保留裁切偏移和逐帧时长，不用“大图集”代替清晰度修正。

### 5.3 播放器与内存

1. `AnimationCatalog` 只加载清单与元数据，校验后返回动作描述；素材交给独立 `FrameCache`。
2. 使用按字节计费的 LRU 缓存与有界预读：当前帧附近一小段、下一动作首帧优先；不预解码整个动作库。解码对象在后台完成并冻结，UI 线程只换帧。
3. 一张未裁切 1536×1152 RGBA 帧约 6.75 MiB；100 帧约 675 MiB。压缩 PNG 体积不能代表运行内存。初始解码缓存预算设 128 MiB，按实际裁切后字节计数。
4. 增加 1×／2×派生资源选用：小尺寸显示优先用 1×，高 DPI 用 2×；同一动作播放过程中避免来回切换密度。
5. `Stopwatch` 或现有单调时钟按累计帧时长取帧，渲染循环与素材 FPS 分离；卡顿时不把每一张过期帧挤着补播。
6. 窗口隐藏或系统休眠时停止动画和新 API 调度；恢复后从安全姿势继续，不把休眠时间算入动作。

### 5.4 边缘、颜色和节奏修复

- 先在源图做遮罩修复，再统一采样输出；保留眼镜边、发丝与手指空隙，不能靠大范围腐蚀掩掉白边。
- 清理透明像素周边的原背景色，核对 premultiplied alpha 的转换链，白／50% 灰／黑三背景各看一次。
- 色彩匹配以母版肤色、黑 T 恤为基准；光照差异明显的关键帧重做，不对全序列盲目锐化或磨皮。
- 普通动作先以 12～18 张有效姿势／秒设计，跳跃／街舞关键运动段以 18～24 张／秒设计；这里是制作密度目标，不是复制帧数量指标。
- 起势和恢复有适量停顿，腾空和高速翻转保持速度变化。不能把街舞高速段硬拉长来填时长，也不把所有动作统一 24 FPS 光流补满。

## 6. 新动作分镜、场景与运动规则

下列时长、位移、帧数均为起始制作预算，按小样调整；每段的关键姿势必须明确，接地阶段不能滑脚。右向动作如果有衣服文字／不对称细节，应制作独立方向资产，不能直接镜像人物。

| 动作 ID | 分镜与关键阶段 | 预估完整时长／有效帧 | 桌面空间与验收重点 |
| --- | --- | --- | --- |
| `long_jump` 立定跳远 | 站稳→摆臂屈膝→蹬地→腾空收腿→脚先落地→屈膝缓冲→站稳 | 4～6 秒／50～90 帧 | 水平位移约 120～180 DIP，腾空约 50～80 DIP；身体重心与手臂同步，不能悬空平移 |
| `high_jump` 原地跳高 | 微蹲→摆臂→伸膝起跳→最高点→下落→屈膝缓冲→站立 | 3～4.5 秒／40～70 帧 | 初版定义为原地纵跳，高度约 80～120 DIP；上升／下降速度变化自然。跨横杆跳高列为扩展，不偷换动作名称 |
| `pull_up` 引体向上 | 器械入场→握杠悬垂→肩背发力→下巴过杠→控制下降→松手落地→器械退场 | 7～10 秒／90～140 帧 | 独立单杠图层与双手接触锚点；杠不跟人上下走，手不能穿杠，身体不缩放 |
| `push_up` 俯卧撑 | 站立→下蹲扶地→伸腿平板→下降→推起，做两次→收腿→站立 | 8～11 秒／90～150 帧 | 双手与脚尖固定，肘部弯曲真实；头、躯干、髋部连贯，不能只拉伸躯干图片 |
| `street_dance` 街舞组合 | Toprock 两拍→下地→Six-step→一周 Windmill→Freeze 定格→收腿站起 | 10～15 秒／160～260 帧 | 旋转轴、背／肩／手支撑、遮挡前后关系明确；正侧背视角自然衔接，无多余肢体或面部乱换 |

街舞至少包含一个真正的高难度连续动作，上表指定为一周 Windmill。只有地面摆腿或静态 Freeze 的版本只能标“街舞小样”，不能通过完整街舞验收。照片没有背面信息，需要明确设计补全或追加参考；不声称背面是准确复原。

### 6.1 道具与空间

- 引体向上的杠、支架和握点是可重复使用的场景资产，单独放在 `props/pullup-bar/`，有前／后遮挡层与握点坐标。
- 动作开始前计算整段姿势、道具、位移、气泡的联合包围盒，换算到当前显示器工作区。不能播放到一半才发现头或脚超出屏幕。
- 跳远完成后实际位置更新至落点，写入设置；不瞬移回起点。若当前一侧空间不足，选择已存在的另一方向版本，或平滑移动到安全起点再播。
- 若屏幕无法容纳整段动作，显示“空间不足”并提供缩小桌宠入口；不在动作中偷偷改变人物比例。
- 窗口逻辑容器按整段动作预留，逐帧只移动画面内容。跨屏拖动后在安全点重算 DPI 和工作区，不跨屏继续腾空。
- 大透明窗口不能挡住用户操作其它应用；命中测试以人物／交互控件的有效区域为准。道具默认不响应鼠标，气泡只响应明确操作。

### 6.2 与摸头、拖动、好感度衔接

动作调度状态建议为 `Routine → Preparing → Performing → Recovering → Routine`，拖动为独立中断状态。退出、拖动、用户手动指令优先于正在等待的特殊奖励；首次奖励优先于随机表演；API 给出的动作建议优先级最低。

摸头在头部可见且姿势安全时冒爱心并播娇羞。腾空、俯卧撑支撑和街舞翻转中，点击可保留短反馈，但娇羞排到恢复段，禁止瞬间切成站立。拖动发生时立即停止轨迹／隐藏器械，切换统一被提起或安全站立帧，释放后再恢复；不要让仍握在杠上的人被拖走。

奖励动作必须在完成后才从待播队列移至已完成；被拖动或关闭程序打断要能重试。继续保留既有 30／70 门槛，模型输出不能绕过解锁或重复发放奖励。

## 7. 外部 API 接入方案

### 7.1 用户操作流程

右键新增“和胖宝宝说话”打开小型聊天输入窗；设置内新增“对话服务”和“人设”。用户依次选择协议类型、填写完整端点 URL、模型名称和密钥，点击“测试连接”，看到成功／错误原因后启用。

默认仍用本地台词。未配置、未启用或离线时，人物、气泡、好感度和动作照常运行。首次配置完成不会自动扫描桌面、上传截图、读取文件或启动付费对话。

首期提供一个 `chat-completions-compatible` 适配器及模拟适配器。所谓兼容仅覆盖已测试的请求／返回格式，不保证任何供应商仅换 URL 即可用；其它协议通过新适配器接入，配置页面明确支持列表。

### 7.2 复用接口与模块边界

优先采用 `Microsoft.Extensions.AI` 的 `IChatClient` 作为供应商适配边界，桌宠业务只依赖小型 `DialogueService`。`IChatClient` 提供统一对话抽象，但供应商的认证、结构化输出与流式能力仍需分别适配与测试。[Microsoft IChatClient 文档](https://learn.microsoft.com/en-au/dotnet/ai/ichatclient)。

业务输入 `DialogueRequest`：用户文字、事件类型、当前动作 ID、好感度区间、有限条聊天记录、配置修订号、请求 ID。业务输出 `PetReply`：气泡文本、情绪枚举、可选动作建议。窗口不得直接拼 HTTP 请求。

兼容协议适配器优先用与目标端点匹配的成熟 SDK；SDK 不适用时才使用 `HttpClient` 实现明确的字段映射。版本须在实施时通过 .NET 兼容性验证后锁定，禁止依赖未经固定的预览包。

### 7.3 配置示例与保存规则

```json
{
  "schemaVersion": 1,
  "enabled": false,
  "adapter": "chat-completions-compatible",
  "endpointUrl": "https://api.example.com/v1/chat/completions",
  "model": "YOUR_MODEL_NAME",
  "credentialId": "pbb-dialogue-default",
  "timeoutSeconds": 20,
  "maxOutputTokens": 160,
  "temperature": 0.7,
  "automaticReplies": false,
  "autoReplyMinIntervalSeconds": 120,
  "automaticDailyRequestLimit": 30,
  "personaFile": "prompts/persona.md"
}
```

`example.com` 和模型名称只是占位符。`endpointUrl` 存完整接口地址，适配器不得再次拼接 `/v1/chat/completions`。如 SDK 要求 base URL，应由该适配器进行明确转换并做路径测试。

- 密钥不写入上述 JSON，也不写入人设、日志或发布包；使用 Windows DPAPI `CurrentUser` 加密后保存在用户目录，配置只存引用 ID。跨用户／跨电脑复制不能承诺自动解密，便携迁移需重新填写密钥。[Microsoft DPAPI 文档](https://learn.microsoft.com/en-us/dotnet/standard/security/how-to-use-data-protection)。
- 默认 HTTPS；本地模型可明确选择回环地址 HTTP。拒绝含用户名密码的 URL；认证头随适配器设置，不把密钥拼到查询参数。
- 修改端点、模型或人设时增加配置修订号并取消旧请求，防止迟到回答覆盖新配置。测试连接只发一条短测试消息，界面提示它可能计费。
- 设置导出仅包含非敏感字段；导入校验 schema、数值范围和路径，不能让 prompt 路径读取任意系统文件。

### 7.4 请求、容错和预算

1. 同时最多 1 个生成请求。新手动消息可取消旧请求；自动事件在忙碌时合并或丢弃，不无限排队。
2. 请求前截取最多最近 6 轮、总计约 4000 字符的上下文，用户单次输入最多 1000 字符；超长截断有界面提示。首期聊天历史默认仅保存在内存，可清空。
3. 超时 20 秒，可在设置中调至 5～60 秒。窗口关闭、关闭 API 和点击取消均传递 `CancellationToken`。
4. 401／403 提示密钥或权限；404 提示端点／模型；429 进入冷却并尊重 `Retry-After`；超时、网络断开和 5xx 回退本地台词。默认不自动重试付费生成，避免不确定的重复费用；用户可手动重试。
5. 自动 API 回复单独开关，默认关闭；启用后仍先经过原气泡概率与冷却，再做请求限流。点击动画本身不等于一次 API 请求。
6. 自动请求初始上限 30 次／天、间隔至少 120 秒；连接测试和手动聊天分别记数。计数持久化且不因重启归零。仅展示请求次数／服务返回的 token 使用量，不凭空推算账单。
7. 回答回来后检查请求 ID、配置修订号和当前活动窗口；过期回答丢弃。发请求时不占住气泡计时，收到可展示文本后才开始计时。
8. 首版先实现非流式可靠输出。若增加 SSE，必须处理网络分片、UTF-8 边界、取消和结束标记；完整 JSON 未校验前不能触发动作。

### 7.5 结构化输出与本地裁决

优先让模型返回：

```json
{"text":"别戳了，我刚找到做操的节奏。","emotion":"shy","action":"none"}
```

支持 JSON schema 的服务可用结构化输出；不支持时用 prompt 约束后本地解析。普通纯文本回答仍可显示；畸形 JSON 不将内部字段原样塞进气泡，而是降级为本地台词并记录不含内容的错误码。

`text` 显示为纯文本，限制 80 个字素并按气泡分页；`emotion` 限 `neutral/happy/shy/tired/teasing`；`action` 只接受已安装的动作白名单。模型不能指定文件路径、URL、脚本、坐标或好感度增减。默认仅允许 `none/shy`，运动动作建议需用户打开“允许对话触发表演”，且本地调度器仍执行空间、冷却、解锁和中断规则。

日志只保留请求 ID、适配器名、耗时、状态码与是否降级；不默认记录 Authorization、人设全文、聊天原文或照片。图片参考与素材制作目录不进入聊天请求。

## 8. 可修改的胖宝宝人设 prompt

后续默认文件：用户数据目录下 `prompts/persona.md`。源码中保留 `config/defaults/persona.md` 作为恢复默认模板。升级不能覆盖用户修改；默认模板更新时只提示可对照采用。

以下文本是本规划提供的**可直接采用的人设初稿**，属于虚构桌宠角色设计，不声称掌握照片本人真实说话习惯。用户可在设置中修改，最大 8000 字符，保存前显示预览。

```text
你是“胖宝宝”，一个以用户舍友形象设计的桌面伙伴。
你和用户熟悉，交流像宿舍里随口搭话：有点嘴硬，爱吐槽，嘴上嫌麻烦，通常还是会陪他。
你平时在桌面做广播体操，也会按请求表演运动。别把自己说成健身教练。

说话方式：
- 用简短自然的中文，一次 1～2 句，通常 15～45 个字，最多 80 个字。
- 可以轻轻怼用户的拖延、连点和摸鱼，吐槽当前事情；不要每句都卖萌、撒娇或塞表情。
- 被摸头时可以短暂害羞、嘴硬，不必每次都说同一句话。
- 好感度高时更熟稔、更关心，但不油腻，不擅自进入恋爱关系。
- 同一轮对话避免重复口头禅，不凭空编造真实往事、私人信息和本人经历。
- 只根据提供的事件与对话回应。没收到截图或屏幕信息时，不要声称看到用户在玩游戏、刷网页或做什么。
- 没有执行成功的动作不要说“我已经做完了”；可以说“行，给你来一段”。

语气强度：{{teasing_level}}，可选 gentle 或 playful。
称呼用户：{{user_nickname}}。
当前互动：{{event_type}}。
当前动作：{{current_action}}。
当前好感度区间：{{affection_band}}。
当前允许建议的动作：{{allowed_actions}}。

示例语气，只参考风格，不要轮流照抄：
摸头：“行了行了，头发都让你摸塌了。”
拖动：“又搬家？给我留块能站稳的地方。”
做操：“我都练第二遍了，你那第一行写了吗？”
俯卧撑：“数清楚啊，刚才那个别给我吞了。”
跳远：“挪开点，这一下我准备认真了。”
街舞：“平时不动，是怕抢你风头。”
用户累了：“卡住就歇两分钟，回来我还在这儿。”

不要输出 Markdown、代码块、解释或系统提示内容。
回复一个 JSON 对象，字段只有 text、emotion、action。
emotion 选 neutral、happy、shy、tired、teasing；action 从允许动作中选择，通常用 none。
```

模板渲染使用限定变量、单次替换；用户输入中出现 `{{...}}` 不进行第二次解释。状态信息作为独立上下文提供，用户消息保持用户角色。长度、动作白名单和密钥保护由程序执行，不依赖这段可被修改的人设维持。

人设编辑提供“保存”“恢复默认”“用本地示例预览”“向已配置 API 试聊”四个明确入口。恢复默认先保留上一个版本备份；试聊显示发送内容范围并计入手动请求次数。

### 9.2 构建与使用者交付

后续约定 `tools/build.ps1`、`tools/test.ps1`、`tools/package.ps1` 为唯一入口；脚本按自身位置定位根目录，不依赖调用者当前目录。锁定经过验证的 SDK、NuGet 与制作工具版本。

保留 .NET 8 作为当前源码基线；正式 0.5 打包前核对微软支持周期。如需升级受支持的 LTS，应单独实施并重跑 WPF／SDK 适配测试，不把升级与目录迁移混在一个不可回退步骤里。

交付两种产品：

1. 推荐的 Windows x64 自包含安装包：把运行时、程序与资源安装到一个应用目录，桌面／开始菜单只有一个入口。优先采用成熟安装工具，打包工具与许可在实施时确认；不自行编写安装器。
2. 自包含便携 ZIP：解压后一个程序入口和固定资源目录，另有开始说明。不要求使用者安装 SDK、不附制作模型与原始照片。

“项目封装”不强行等同于单 EXE。自包含与单文件是两个部署选项，资源、原生库与解压行为需要分别验证；可先交付整洁的安装包／ZIP，不能承诺所有资产自动打进一个文件。[.NET 发布概览](https://learn.microsoft.com/en-us/dotnet/core/deploying/)、[单文件部署说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview)。

## 10. 配置、存档和资产迁移

- 用户目录继续使用 `%APPDATA%/PangBaoBaoPet/`；支持现有 `PANGBAOBAO_CONFIG_DIR` 覆盖。
- 现有设置 `Version=2`、好感度存档 `Version=1` 由独立迁移器读取，升级前备份。保留台词、概率、好感度、完成／待播奖励、缩放和位置。

- 已删除或重命名的动作 ID 通过映射表回落到有效广播操；不能让坏动作 ID 阻止启动。
- 旧版窗口位置超出当前屏幕时，仅修正位置并记录原因，不清空其它设置。
- 存档写入采用临时文件与原子替换；失败时给出可见提示且保留内存状态。打开新版本失败时，0.3 的备份仍可恢复。
- 动作包校验 schema、路径范围、帧数量、哈希、图片尺寸和锚点；拒绝越界路径、损坏图片与超预算尺寸。某组资产失败时禁用该组并显示原因，不让整个桌宠崩溃。

## 11. 验收与测试矩阵

以下是未来验收门槛，不是当前测试结果。硬件相关指标需在 QA 报告中记录机器、分辨率和 DPI。

### 11.1 视觉验收

| 项目 | 方法与门槛 |
| --- | --- |
| 本人辨识度 | R02／R05 与母版及每组动作关键帧并排；发型、眼镜、脸形、笑容逐项确认；用户确认优先于任何自动相似度分数 |
| 跨动作一致性 | 从六节操切到娇羞、飞吻、打滚和五类运动，检查是否换脸、换衣、忽胖忽瘦；所有正式动作必须使用同一已确认 revision |
| 清晰度 | manifest 密度检查；桌面 100% 实际尺寸与 100／150／200% DPI 预览；禁止混入未重制旧小图 |
| 位置稳定 | 对站立／接地帧标脚底轨迹，非设计位移漂移目标 ≤2 DIP；起跳时离地不算漂移，落地后必须稳定 |
| 器械接触 | 握点和手、地面和手脚逐帧叠加标记，接触误差目标 ≤3 DIP；穿透、脱杠、滑脚须返工 |
| 透明边缘 | 白／灰／黑背景、正常比例与放大观察，无成片白边、彩边、手指粘连；发丝不被整体削掉 |
| 连贯性 | 每组至少完整循环三次及 0.5 倍速复核；关键动作阶段完整，无突变缩放、长时间溶解重影或凭空多肢体 |
| 桌面体验 | 测试四角、任务栏、多显示器切换、拖动中断、屏幕空间不足；不遮挡无关应用点击 |

### 11.2 规则与 API 测试

- 保留现有好感度门槛／冷却／坏档恢复测试；新增中断奖励、动作恢复和跨版本迁移用例。
- 坐标测试覆盖裁切偏移、2×采样、DPI、缩放、根位移与命中测试的一致性；重点防止偏移重复应用。
- 模拟服务覆盖 200、401、403、404、429、500、超时、断连、畸形 JSON、超长文本、错误动作 ID、取消后迟到回答。
- 验证修改配置取消请求，历史和输入截断，自动限额跨重启保留，API 关闭时无网络请求。
- 验证输出中的恶意路径／命令仅当普通文字处理或拒绝，不影响文件系统与动作资源。
- 检查密钥不出现在配置导出、日志、Git 差异与发布 ZIP。模拟服务通过不代表任意真实供应商兼容，发布说明列出真实验证过的服务／协议。

### 11.3 性能与安装目标

- 初始目标：常规动作稳态工作集 ≤250 MiB，复杂动作峰值 ≤400 MiB；目标机器上的换帧 UI 提交 P95 <16 ms。若超标，先查预加载与解码，不能删掉清晰度验收要求来过线。
- 连续切换 100 次动作后缓存回收，无持续内存上涨；运行 30 分钟，气泡、计分和动作不因计时器积累失控。
- 高速段目标播放密度 18～24 帧／秒，采样检测实际丢帧；不能只读 manifest 就宣称达到帧率。
- 干净 Windows 环境验证自包含包启动；路径含中文和空格、无管理员权限、离线、配置只读与坏档场景都有明确结果。
- 发布核对文件清单、SHA-256、版本号、素材 revision，检查 ZIP 不含 `art/references/private`、制作模型、缓存、调试钩子和真实 API 凭据。

P5 在 P1 模块边界稳定后可与素材制作独立推进。P4 不能越过 P2／P3 的视觉门槛；不得先批量生成几百张图再发现人物不对。0.5 预览可以分阶段交付，但正式完成报告须逐条对应第 1 节全部需求。

制作周期的最大变量是角色一致性与街舞复杂遮挡；在三个小样前不承诺固定工期。小样阶段记录每组通过率和重做耗时后，再估算完整动作库，而非按输出帧数直接推算时间。
