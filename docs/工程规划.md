# 胖宝宝独立桌宠工程规划

版本：规划稿 v1.0 · 2026-09-23

状态：已按本规划启动工程。本文保留原始目标与验收条件；实际进度、取舍和未完成项见 [工程验证记录](../工程验证记录.md)。

## 1. 产品目标与已确认约束

做一个可独立运行的 Windows 桌宠，让照片中的“胖宝宝”在桌面上做广播体操，并偶尔用用户设置的文字弹出对话气泡。

已确认要求：

- 保留原照片风格，脸、眼镜、发型和衣服具有辨识度。允许轻微二维变形；避免过度卡通化、幼化。
- 广播体操是主要内容，有多个动作和状态，并提高动作的连续性与流畅度。
- 修正手臂偏短问题；举起、平举、放下时保持合理且一致的身体比例。
- 独立桌面端运行，不依赖 Codex 才能显示和交互。
- 气泡内容可设置，随机出现概率可调。
- 优先采用成熟桌宠项目、动画工具和现成组件。

本文中的默认数值、首版动作数量和打包形式属于工程建议，开发时可以调整，不视为用户已逐项确认。

## 3. 首版功能范围

### 3.1 桌面运行

建议首版提供透明背景、拖动、缩放、置顶开关、暂停动画、托盘入口及退出功能。保存位置与大小，重启后恢复；显示器布局变化时能够回到可见区域。

建议交付可双击启动的 Windows 程序包，并附运行说明。优先评估便携包；运行环境是否随包携带，在选型验证阶段确定。仅能在 Codex 中显示的素材包不能作为本项目交付。

### 3.2 广播体操与动作控制

建议首版动作包括：自然站立、伸展、扩胸、左右侧弯、转体、体前屈、踮脚，以及动作之间的收势过渡。具体节数以通过形象与动作验收的素材为准。

用户可以选择单节循环或整套播放，并调整动作播放速度。动作切换优先在收势位置完成；拖动结束后回到可衔接的姿势。动画速度和气泡触发频率分别控制。

建议以 24 FPS 动画素材作为首个流畅度目标，再根据桌面实测决定是否提高到 30 FPS。提高播放速度或重复已有图片不算新增运动细节；必须检查关键姿势之间是否有自然的中间运动。

### 3.3 对话气泡

- 设置界面可增删改多条文案，单条可启用或停用，支持中文与自动换行。
- 随机命中后，从启用的文案中抽取一条；多条可用时尽量避免连续重复。
- 出现概率可调到 0–100%，同时展示判定间隔，避免“概率”含义不清。
- 提供最短冷却时间、气泡停留时间和总开关。
- 同时最多显示一个气泡；到时消失，点击可提前关闭。
- 气泡跟随桌宠，避开脸部；靠近屏幕边缘时选择有空间的一侧显示。
- 使用本地文案库并保存设置，首版无需接入语言模型。

可选的后续功能：给文案设置权重、按“开始做操／做完休息／被拖动”等场景分类，以及勿扰时段。这些功能不阻塞首版交付。

## 4. 气泡概率的明确规则

建议采用“定时判定 + 概率抽取 + 冷却”机制。配置示例：每 5 分钟判定一次，命中概率 20%，显示 5 秒，消失后至少安静 10 分钟。以上只是建议默认值。

每次判定按以下顺序执行：

1. 检查总开关、桌宠是否可见、是否有启用文案、是否已有气泡及冷却是否结束。
2. 条件满足时才进行一次随机抽取；命中后显示一条文案。
3. 气泡消失后开始冷却。冷却期间跳过判定，不积攒待显示消息。
4. 电脑从休眠恢复或桌宠重新显示后重新安排判定，不补发离开期间的气泡。

0% 表示随机气泡不会出现；100% 表示每次符合条件的判定都会触发，仍受冷却和单气泡限制。20% 不表示每五次一定出现一次，也不保证固定的实际间隔。

## 5. 技术选型与复用边界

### 首选候选：VPet

此前核对的官方项目资料列出了独立桌面应用、动画模组、说话文本、`MessageBar` 气泡组件，以及可嵌入 WPF 应用的核心。它比单纯播放动画的工具更贴近本次完整需求。

后续验证分两步：

1. 在现成 VPet 运行环境中验证一段自定义动画和一条自定义气泡，确认素材接入方式。
2. 验证独立交付方式。优先复用 VPet 核心及显示组件；若采用现成宿主加模组的方式，需要明确用户启动方式和外部依赖，确认其符合独立桌面端要求。

原生概率配置能力尚未确认。若现成设置满足需求，直接复用；否则通过插件接口补充定时判定、冷却、文案管理与持久化。动画播放、透明窗口和气泡显示优先使用现成能力。

### 备选与转换条件

| 方案 | 适用位置 | 启用条件 |
| --- | --- | --- |
| OpenAnima | 透明动画播放验证 | 用于素材验证；完整气泡功能尚未证实，暂不作为首版最终选型 |
| Shimeji-ee | 动作与桌宠行为候选 | 仅在 VPet 不适配时继续核对帧率、气泡和打包成本 |
| Qt / Godot 等通用框架 | 有限的备选实现 | 现成桌宠项目存在明确阻碍时，先记录阻碍与新增开发范围，再调整方案 |

不因为单一功能尚未核对，就直接更换整个桌宠运行方案。

## 6. 动画生产方案

1. **建立形象基准。** 以原照片核对脸、眼镜、发型、肩宽、手臂长度与睡衣样式，形成标准站姿和关键姿势参考。
2. **选择一节伸展做完整样片。** 先处理双臂举起再放下，验证相同人物纹理在连续运动中的稳定性。
3. **评估 Live2D 分层与变形。** 将躯干、上臂、前臂、手等合理分层，在成熟工具内制作关节运动。遮挡后露出的区域需要补图；大幅转身和前屈不能仅靠拉伸正面图解决。
4. **导出逐帧透明素材。** 首先尝试 24 FPS，保留原始分层文件、动画工程和导出设置。
5. **检查桌宠实际尺寸下的效果。** 同时查看浅色、深色背景，检查脸部稳定、手臂长度、透明边缘、脚底漂移和循环接缝。
6. **通过样片后扩展动作。** 复用已验证的模型、材质与制作规范，逐节增加体操动作。

RIFE 等插帧工具作为可选的离线辅助步骤：适用于连续性良好的相邻画面，需要检查手指、眼镜和遮挡处。此前下载未成功，不能将其记为已可用依赖。

## 7. 逻辑职责与数据

| 职责 | 内容 | 优先复用 |
| --- | --- | --- |
| 桌面显示与交互 | 透明显示、位置、拖动、托盘 | 桌宠宿主或核心 |
| 动作控制 | 动作选择、速度、循环、过渡 | 现成动画接口 |
| 气泡显示 | 文本排版、定位、关闭 | 现成气泡组件 |
| 气泡调度 | 判定间隔、概率、冷却、去重 | 原生配置优先，必要时小插件 |
| 设置界面 | 文案编辑与参数调整 | 现有设置扩展入口 |
| 本地配置 | 保存、读取、导入导出与版本兼容 | 现有设置系统优先 |

配置至少包含：气泡开关、判定间隔、命中概率、冷却时长、显示时长、文案列表，以及桌宠位置、缩放和动作设置。空文案库时暂停随机气泡；配置损坏时使用备份或明确提示恢复默认。保存应避免写到一半损坏旧配置。

## 8. 分阶段执行计划与完成条件

以下为原定阶段与完成条件；实际执行结果以工程验证记录为准。

| 阶段 | 工作与交付物 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 现成方案验证 | 固定 VPet 候选版本；验证透明帧、自定义气泡、概率配置或插件入口、独立启动路径 | 有实际运行证据；明确可复用范围、缺口和打包依赖 |
| P1 单节动画样片 | 标准形象、可编辑动画工程、一节 24 FPS 伸展样片 | 用户确认像本人、手臂自然；无明显变脸、断肢或循环跳变 |
| P2 桌面最小可用版 | 独立启动、拖动缩放、播放伸展、托盘退出 | 在目标 Windows 环境中完整运行与退出，位置恢复可用 |
| P3 气泡功能 | 文案设置界面、概率与冷却、本地保存 | 文案可改且重启保留；0%/100%及冷却逻辑符合定义 |
| P4 动作扩充 | 多节广播体操、整套播放、自然过渡 | 每节完成视觉检查，切换与循环无明显跳变 |
| P5 打包与验收 | 可启动程序包、说明、版本信息、依赖及许可清单 | 新目录或干净测试环境中可运行，程序包包含真实可用的功能 |

P0 和 P1 可以分别缩小运行方案与视觉方案的不确定性；完整集成以两者都通过为前提。具体工期在这两个阶段完成后再估算，避免用未经验证的动画制作速度承诺交付时间。

## 9. 验证重点

- **人物与动作：** 对照原照片检查辨识度和比例；看完整循环及动作切换；高帧率素材与实际桌面播放分别验证。
- **气泡规则：** 用可控时钟和随机数验证概率边界、冷却、关闭、空文案库和恢复后的行为，避免等待真实的长时间间隔来测试。
- **设置保存：** 修改后立即生效，重启保留；非法数值有边界处理，损坏配置可恢复。
- **桌面交互：** 检查拖动、缩放、屏幕四边、常用 DPI、显示器变化、暂停和托盘退出；气泡不能抢走正在输入的窗口焦点。
- **性能：** 在目标电脑记录待机、播放和显示气泡时的 CPU、内存及卡顿情况。性能阈值依据 P0 实测制定，不能凭素材帧数宣称已经流畅。
- **分发：** 从最终程序包启动，确认不依赖开发目录中的临时图片、脚本或个人绝对路径。

## 10. 主要风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 多次生成导致人物与花纹跳变 | 尽早固定形象与分层模型，减少逐帧重新生成整个人物 |
| 手臂长度再次不一致 | 使用同一模型的肢体长度，逐姿势核对；修正版也需视觉确认 |
| 大幅动作出现纸片感或遮挡缺失 | 为复杂动作补专用姿势或视角，先通过单节样片再扩展 |
| 桌宠宿主限制气泡位置或动画帧率 | 在 P0 核对接口和实际效果，避免后期才发现限制 |
| 概率设置造成刷屏或长时间无反馈 | 明确判定间隔和冷却含义，提供“预览一条气泡”的设置入口 |
| 透明边缘和鞋部细节损坏 | 保留高质量源图，检查深浅背景下的透明轮廓 |
| 打包依赖影响独立运行 | 在 P0 明确依赖，在 P5 使用干净环境验收 |
