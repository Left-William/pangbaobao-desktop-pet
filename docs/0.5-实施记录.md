## 视觉检查与明确缺口

`python tools/assets/validate_assets.py` 检查到 18 个动作条目、0 个结构错误、**90 帧低于 2 源像素／显示 DIP**。主要集中在睡衣版旧广播操和互动动作。`--release` 还报 25 项动作覆盖／最少帧数／预览命名缺口；正式候选打包会因此失败。不能用文件放大或复制帧来冒充清晰度修复。

## 对话接口边界

目前只有 `chat-completions-compatible` 非流式适配器，使用完整端点 URL，不自接路径。服务未配置时使用本地台词；手动请求上限 1000 字，系统人设上限 8000 字，响应上限 64 KiB，回复文字上限 80 字素。HTTPS 或回环 HTTP 可用，明确拒绝 URL 中的账号和片段。请求在窗口关闭、点击取消、保存新配置或人设时取消；解析后的动作仅限白名单，最终还由本地播放器检查是否安装。

自动回复默认关闭；开启后仍先经过原气泡概率与冷却，成功命中才尝试 API。自动请求每天最多 30 次、至少间隔 120 秒，次数跨重启保存在用户目录；429 按服务的 `Retry-After` 冷却。手动聊天仅保留最近六轮内存历史，单次请求最多附带约 4000 字符。默认人设中的 `{{...}}` 变量单次替换；未安装的动作即使被模型提议也不会执行。尚未做真实供应商兼容测试、完整运行态费用观察和会话导出；任何真实密钥只在用户本机填写。

3. 完成固定舞台坐标、根位移、头／嘴／接触锚点、道具独立层与空间预检，记录两套皮肤下逐动作清晰度和接地结果。
4. 重制旧广播操、娇羞、飞吻、打滚，再完成五类运动，双服装分别过完整动作验收。`--strict` 归零后再做 0.5 Release。

```powershell

python .\tools\assets\validate_assets.py --strict
python .\tools\assets\validate_assets.py --release
```

前三项当前分别为构建成功、规则与模拟 API 测试通过、结构检查通过但报告 90 帧清晰度不足；严格清晰度与发布门槛均预期失败。`package.ps1 -ReleaseCandidate` 会先执行发布素材门槛与测试；普通打包成功只表示可生成预览 ZIP，不表示 0.5 视觉完成。
