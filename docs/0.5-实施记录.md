## 视觉检查与明确缺口

`python tools/assets/validate_assets.py` 检查到 20 个动作条目、0 个结构错误、**72 帧低于 2 源像素／显示 DIP**。主要集中在睡衣版旧广播操和互动动作。`--release` 报 34 项动作覆盖／最少帧数／不同文件数／预览命名缺口；正式候选打包会因此失败。不能用文件放大或复制帧来冒充清晰度修复。

用户已看过黑 T 恤与睡衣站立截图，并确认“基本像，可继续”；这只通过人物身份方向的制作门槛。两张图片写入 `art/masters/character.json`，修订号 `pbb-photo-05-approved`，校验脚本逐个核对文件哈希。跳高／跳远补了发力与落地缓冲，目前各六个运行帧、五张不同画面，仍远少于规划的 40／50 张，也未做桌面原尺寸连续播放验收。引体候选的单杠与灰色背景混成同一图层，不符合独立道具要求；俯卧撑候选姿势尚缺上下往复，街舞候选只有一张 Windmill 姿势，不能称作完整街舞。这三张均只存于 Git 忽略的 `art/candidates/black-tee/`，没有进入发布菜单。

已从早期 0.5 预览 ZIP 启动两个隔离配置的进程，用 Win32 `PrintWindow` 分别捕获 [黑 T 恤站立](qa/v0.5/runtime-black.png) 与 [睡衣站立](qa/v0.5/runtime-pajamas.png)。两者窗口均为 538×613 物理像素，人物能够出现且衣服没有交叉；截图背景呈黑色，不能据此判定白／灰底的透明边缘质量。黑 T 恤站立运行约 5 秒时进程工作集约 230.5 MiB（当前机器、单次采样，仅作基线）；复杂动作峰值和换帧 P95 尚未测。运行进程在捕获后已关闭，未改用户的日常设置。当时伸展举臂姿势还只是 Git 忽略目录里的候选；本轮已筛选后接入运行帧。

## 对话接口边界

目前只有 `chat-completions-compatible` 非流式适配器，使用完整端点 URL，不自接路径。服务未配置时使用本地台词；手动请求上限 1000 字，系统人设上限 8000 字，响应上限 64 KiB，回复文字上限 80 字素。HTTPS 或回环 HTTP 可用，明确拒绝 URL 中的账号和片段。请求在窗口关闭、点击取消、保存新配置或人设时取消；解析后的动作仅限白名单，最终还由本地播放器检查是否安装。

自动回复默认关闭；开启后仍先经过原气泡概率与冷却，成功命中才尝试 API。自动请求每天最多 30 次、至少间隔 120 秒，次数跨重启保存在用户目录；429 按服务的 `Retry-After` 冷却。手动聊天仅保留最近六轮内存历史，单次请求最多附带约 4000 字符。默认人设中的 `{{...}}` 变量单次替换；未安装的动作即使被模型提议也不会执行。尚未做真实供应商兼容测试、完整运行态费用观察和会话导出；任何真实密钥只在用户本机填写。
